Contract memory harness

A small agent harness and eval for one question: when an agent works over a firm's contract bank, does a memory built ahead of time answer as well as rereading the contracts, at a fraction of the tokens, and what happens when a contract is amended? Five public contracts from CUAD, 25 questions, a tool-using agent, and a plug-in slot where a learned memory (such as an Engram) would go.

Model: claude-cli:sonnet (served as claude-sonnet-5-5; Claude Code in print mode, no tools, the harness's own system prompt). Every model call is recorded in runs/latest/calls.jsonl, so the grades below can be re-checked with python -m cmh.run --replay runs/latest and no API key. 1. Answer quality and cost on the contract bank

25 questions: 18 single facts, 4 terms the contract does not contain (the right answer is “not there”), and 3 that need several contracts. Grading is a fixed rubric (exact figure present, right contract cited, no made-up terms), not a model judging a model. Figures must match as whole numbers, so “5,000” does not match inside “4,500,000”. Citing a contract that the answer checked and ruled out is not penalized; the first version of the rubric did penalize it and failed four correct answers. Cross-contract answers are graded on recall only (every right contract named), not on precision.

Changes since the first published run, which is kept in runs/v1_topic_list_notes: the note-writing prompt no longer lists the clause types the questions ask about (it now asks generically for the terms a lawyer would be likely to ask about), and the grader now matches whole figures. The numbers below are from a fresh live run with both changes in place; it is a single run, so a one-question difference is within run-to-run noise. The grades shown are the recorded answers re-graded with the final grader; how the run was graded live is in runs/latest/results_as_recorded.json.

3. Plugging in a learned memory

Every config implements the same small interface in cmh/memory.py: build(corpus) runs offline, context(question) returns what goes in the prompt, and stale_docs(corpus) says which contracts the memory no longer matches. EngramMemory is the empty slot: with access, build() would train or point at an engram for the bank, context() would send little or nothing, and the same 30 questions would score it next to the baselines on accuracy, tokens and latency.

How to run

python -m cmh.run --model claude-cli:sonnet (Claude Code in print mode) or --model api:claude-sonnet-5-5 with ANTHROPIC_API_KEY; python -m unittest discover -s tests -t . runs the tests with no model.
